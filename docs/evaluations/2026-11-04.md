## What passed

- **Login check:** every write (reviews, likes, replies, reports,
  log-out) answers 401 with no login and with a fake login, in a
  friendly sentence.
- **CORS:** the live site and localhost are allowed; `https://evil.example`
  gets no `Access-Control-Allow-Origin`; PUT is not allowed.
- **Act-as-traveler:** every insert, update and delete runs inside
  `travelerTransactions.run`; SQL uses `$1` parameters, never glued text.
  `?category=' or 1=1--` answers an empty list.
- **RLS:** on for all 7 tables with a policy per action; `review_reports`
  has no read policy; the example `notes` table was dropped in 015;
  Realtime (029) does not include `review_reports`.
- **Privacy and secrets:** no answer carries an email (reviews,
  traveler profile); no real `sb_secret_` key or JWT in the repo; no
  `.env` file tracked.
- **Validation:** `/near` refuses bad `lat`, `radius_km` ≤ 0 or > 200
  with plain sentences.
- **Server HTML:** `lang="en"`, one `<h1>` per page, every image has alt
  text, buttons and inputs named or labelled.
- **Motion** follows "reduce motion" (`Providers.tsx`); pop-ups use the
  browser's `<dialog>` (Escape closes, focus stays inside).

## Findings

### A. Spec

- **[Low] A1 — Badly formatted ids get a technical message, before the
  login check.** `DELETE /v1/reviews/1` with no login answers 400
  "Validation failed (uuid is expected)" instead of 401. Also:
  `GET /v1/reviews` without parameters → "The value passed as UUID is
  not a string"; malformed JSON → the parser's own text; an unknown
  destination → "Destination 1111… not found". `backend.md` asks for
  plain sentences.
  - Checked with: curl against the live backend.
  - Cause: NestJS's built-in `ParseUUIDPipe` runs before the
    controller and uses its own wording.
  - Fix: `new ParseUUIDPipe({ exceptionFactory: () => new NotFoundException("We couldn't find that review.") })`.

### B. Safety, standards, UX and accessibility

- **[Medium] B1 — A broken place link shows "Error: Request failed with
  status code 400".** On `/destinations/abc` (and accommodations).
  - Where: `src/components/PlaceDetail.tsx` (`PlaceNotFound`).
  - Cause: the "not found" page printed the network library's error
    text under the heading.
  - Fix: a friendly sentence instead, and a different one when the
    backend could not be reached. **Fixed 2026-11-05 — see below.**
- **[Medium, accessibility] B2 — Every destination and accommodation
  tab is titled "Lakat Iloilo".** WCAG 2.4.2 Page Titled.
  - Where: `src/app/destinations/[id]/page.tsx`,
    `src/app/accommodations/[id]/page.tsx` (no `generateMetadata`).
  - Fix: name the place in the title, like the traveler page.
    **Fixed 2026-11-05 — see below.**
- **[To verify, likely Medium, accessibility] B3 — Login field focus may
  be too faint.** `GlassField.tsx` removes the input's focus ring; the
  only sign is the border going `white/25` → `white/60`. May miss the
  3:1 contrast of WCAG 2.4.7 / 1.4.11. Same check for `white/50`
  placeholders and small `white/60` text on glass cards.
- **[Low] B4 — Unknown pages.** `/nope` shows Next.js's plain default
  404 (no navbar, no link home): there is no `src/app/not-found.tsx`.
  A missing destination answers HTTP 200.
- **[Low] B5 — Security headers.** No `Content-Security-Policy`,
  `X-Content-Type-Options`, `Referrer-Policy` or `X-Frame-Options` on
  the site or the backend; both send `X-Powered-By`. Fine for the demo;
  candidate for `docs/LATER.md`.
