## Each Medium alert, its cause and the fix

1. **Content Security Policy (CSP) header not set**: on the website's
   `/api` (local and live) and on the backend's home page `/` (local and
   live).
   - *Website cause:* the `matcher` in `src/proxy.ts` skipped every address
     starting with `api`, so `/api`, `/api/health` and others showed the
     site's "not found" **page** with no policy.
   - *Website fix:* the proxy now skips only `/api/v1/` (the JSON proxy) and
     `/api/wikimedia-photo` (photos).
   - *Backend cause:* it sent no policy at all.
   - *Backend fix:* `backend/src/app-setup.ts` sends
     `default-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`
     on every answer. The backend only answers JSON or a plain sentence, so a
     browser may run nothing from it. The first re-scan then reported
     "Failure to Define Directive with No Fallback", which is why `base-uri`
     and `form-action` are named too.
2. **CSP: script-src unsafe-inline** (every page, local and live).
   - *Cause:* Next.js puts small inline scripts in each page, and the policy
     allowed every inline script to make that work. So an injected `<script>`
     or `onerror="…"` would also have run.
   - *Fix:* a **nonce**, a random one-time code that is new for every page
     view.
     - `src/proxy.ts` makes it, puts `'nonce-…'` in the policy and hands it
       to Next.js, which stamps it on its own scripts. An attacker's script
       can't know the code.
     - A nonce must be fresh on every visit, so `src/app/layout.tsx` calls
       `await connection()`, which builds every page per visit.
   - *Checked:*
     - Every script on home, login, a place page and `/api` carries the
       nonce (22/22, 17/17, 27/27, 16/16 on the production build).
     - A new browser test shows an injected `<script>` and an `onerror`
       handler are both refused, and neither ran.
3. **CSP: style-src unsafe-inline** (every page, local and live).
   - *Fix:* `<style>` tags need the nonce too.
   - Only `style-src-attr 'unsafe-inline'` remains. It covers `style="…"`
     attributes, which React and the motion library write into the HTML
     (16 on the home page). An attribute can change how something looks but
     can't run code, and ZAP no longer reports it.
4. **CSP: script-src unsafe-eval** (localhost only).
   - *Cause:* only `npm run dev` adds it (React's debugging needs it). The
     live build never had it; the L6 smoke test checks this.
   - *Fix:* the local plans now say to scan a **production build**
     (`npm run build`, then `npm start`), which is what the live site runs.
   - The dev server keeps `'unsafe-eval'` and inline styles.

**5. Cross-Domain Misconfiguration** (`Access-Control-Allow-Origin: *`),
live only, on `/login`, `/admin/login`, `/forgot-password` and
`/admin/reports`.
- *Cause:* these pages were pre-built (static), and Vercel sends `*` with
  static files. The pages hold nothing private.
- *Fixed by item 2:* every page is now built per visit, and Vercel doesn't
  add `*` to those. The existing filter for static images, `robots.txt` and
  `sitemap.xml` stays.

## Plan changes (2026-11-20)

- `baseline-local.yaml` is new. `site-urls-local.txt` and
  `site-urls-live.txt` add the pages, the `/api/v1` proxy, the photo relay
  and the addresses that must answer 404.
- `baseline-live.yaml`: the spider never fills in or sends forms
  (`processForm`/`postForm` off), and the `/api/v1/(auth|admin)` routes are
  out of scope.
- `active-local.yaml`: it now excludes `localhost:3000/api/v1/(auth|admin)`.
  This was the website's side door to log-in and admin, which the attack
  could otherwise have reached through the proxy. It also excludes
  `/api/wikimedia-photo`, so attacks are never passed on to Wikimedia's
  servers.

## Trade-off accepted

**Every page is built per visit now, including `/login` and
`/forgot-password`.** Before, Vercel served those from its cache. That
costs a little server time per visit, and is the price of nonces. The home
page and place pages were already built per visit. Re-run Lighthouse (L8)
after the push to check the vitals stay inside the budgets.

## Not covered

- Pages behind an admin login (ZAP runs without one).
- Logic rules (L3) and RLS (L4).
- The live site, until the fixes are pushed and `baseline-live.yaml` runs
  again.
