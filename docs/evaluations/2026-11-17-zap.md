## Each Medium alert

1. **Content Security Policy header not set** (site ×5, API ×1).
   *Real, accepted for now.* CSP tells the browser which sites the page
   may load scripts, styles and images from, so injected code can't run.
   It is parked in `docs/LATER.md` (see `next.config.ts`), because a
   strict CSP could block the site's photos and fonts. It stays in every
   report until it is done.
2. **Cross-Domain Misconfiguration** (`Access-Control-Allow-Origin: *`).
   *False alarm.* The flagged addresses are `icon.png`,
   `lakat-logo-white.png`, `robots.txt`, `sitemap.xml` and the splash
   image. Vercel lets any website read these public, unchanging files,
   and they hold nothing private. **The part that matters was checked
   separately and passes:** the API refuses other websites (no
   `Access-Control-Allow-Origin` for `https://evil.example`).
3. **Sub Resource Integrity attribute missing** (5 place pages).
   *False alarm.* Every one is `<link rel="preload" as="image">` for a
   place photo. The `integrity` attribute protects scripts and
   stylesheets from other sites; browsers ignore it on images.

Items 2 and 3 are recorded as false positives with **narrow**
`alertFilter` rules in `baseline-live.yaml`: image preloads only, and
static files only. A real script or stylesheet without integrity, or a
page or API answer with `*`, would still be reported.

## Third run, 2026-11-18: DOM XSS on its own step, and what it led to

- The DOM XSS step "completed" on the website (225 s), but loaded **no
  pages** there (0 messages), so it proved nothing.
- **A canary proved the rule works:** a deliberately vulnerable page in a
  scratch folder (deleted afterwards). The same rule and Chrome setup found
  both planted bugs (High) in 13 s.
- **So the website's DOM XSS was tested directly** with Playwright
  (`e2e/flows/address-attacks.spec.ts`): 3 attack strings in `?…` and `#…`
  on the 6 places the website reads its address. No script ran, and no
  injected HTML appeared. ✅
- **The same tests found an open redirect** (Medium): after log-in,
  `?next=/%09/evil.example` (tab) or `/%0A/` (newline) sent the traveler to
  `http://evil.example/`, which a phishing link could use. Browsers delete
  tabs and newlines in addresses, so "/<tab>/evil.example" became
  "//evil.example". **Fixed** in `safeNextPath` (`src/lib/auth.ts`): the
  browser's own URL reader now decides, and only this site is allowed.
  The old version let 3 tricks through (tab, newline, carriage return);
  all 8 are now blocked (16 unit tests, 28 browser runs). The live site
  keeps the old code until the fix is pushed.
