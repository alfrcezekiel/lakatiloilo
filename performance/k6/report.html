The website thresholds are: all checks over 99 % (95 % in stress and spike), security checks exactly 100 %, and pages and /api judged separately against the limit, so a slow page can't hide behind fast data calls. The warm-up visits in setup() are not counted.

What it means for a traveler on demo day

  • Even if 150 people open the site at once, or 100 arrive in one burst after a post is shared, every page and data answer arrives. On the live site, 95 % of them arrive in under 0.3 s.
  • After 30 minutes of steady use nothing got slower: the soaks' p(95) matches the short tests, so nothing leaks or piles up.
  • The security headers did not slip once under load.

Findings

  • The live site is faster than localhost (pages 284 ms against 574 ms under stress). The live website, backend and database all run in Mumbai. On the laptop, the local website and backend reach that database from the Philippines.
  • Two slow single requests, not a pattern: one live backend answer took 26.3 s (live backend load), and one local /api answer took 7.0 s (website soak). Each was one request out of thousands, and p(95) and the error rate did not move. The likely cause is a Vercel function starting fresh, or a network hiccup. The summaries don't record which route it was. If it happens again, run that test with --out json=… to find out.
  • Website answers are heavier than data answers: about 28 KB each in website stress (500 MB over 17,861 requests), against about 9 KB for a backend answer. That is the page HTML, built per visit for the nonce CSP. It is not a problem at this size.
  • The first visit after a deploy is slower (home took 0.85 s cold, then 0.3 s). That is why setup() warms each page before the travelers start. The limit stays at 800 ms.

Not checked

  • More than 150 travelers. No test went past that, so the app's breaking point is not known yet.
  • Live stress, spike and soak on the backend's own URL. The live website tests already reach it through /api.
  • Page speed as a traveler sees it in the browser. That is Lighthouse's job: see the Lighthouse report.
